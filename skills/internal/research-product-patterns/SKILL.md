# Research Product Patterns

## Define the question

Start with one user problem and targeted research questions. Do not browse for attractive screens without a decision to inform.

Capture:

```text
User problem:
Primary user and task:
Business objective:
Trust and density requirement:
Relevant flow/state:
What must feel familiar:
What may be experimental:
```

## Mobbin

Use the already authenticated browser only when the active task needs Mobbin.

- Never request, read, record or store Gmail or Mobbin credentials.
- Pause for manual authentication when required.
- Do not bypass plan restrictions, bulk scrape or reproduce the library.
- Review at least 3 relevant production flows when the free plan permits it.
- Preserve source application names and links.
- Capture only the references needed for the task.

For each reference record the flow, problem solved, effective and ineffective choices, what to adapt and what not to copy.

## Baymard

Use only publicly accessible research. Cite the exact public article or research page. Separate a tested ecommerce finding from Major's inference for recruitment, SaaS or internal tools. Do not force checkout findings onto unrelated workflows.

## Other sources

Supplement selectively with official product demos, public documentation, Page Flows/Refero where legally accessible, existing project brand systems and maintained component libraries. Keep production-product evidence separate from marketing inspiration and experimental ideas.

## Output

Create `design-research/reference-index.md` or the project-equivalent:

```text
User problem:
Relevant reference products:
Observed patterns:
Evidence source:
Applicability to this product:
Risks:
Recommended pattern:
What was deliberately not copied:
How we will test it:
```

Use a reference-to-decision table. Every source needs a specific product decision. Do not produce a vague list of admired brands.

## Handoff

Pass the evidence to `craft-web-interfaces` for substantial UI direction, or directly to implementation when the task is a bounded workflow convention with no material visual-direction choice.

Read [references/research-record.md](references/research-record.md) for the reference schema and source boundaries.
