# MVP Speed Prioritisation

For every new project or large feature request:
1. state the core outcome;
2. identify the biggest uncertainty;
3. choose the fastest credible proof;
4. classify requirements P0 MVP / P1 next / P2 later;
5. build P0 end to end, not all layers/features fractionally;
6. maintain a demonstrable artefact/proof as early as practical;
7. verify the core loop;
8. expand only from observed bottlenecks and evidence.

Speed and learning dominate speculative completeness. Security/QA depth is proportional to actual risk, with secrets/destructive/irreversible production actions always protected.
