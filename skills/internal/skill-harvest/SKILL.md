# Skill harvest

Keep GBrain as durable organizational meaning and Major as the sole routing and activation authority. Record the prior-art decision before substantial helper code.

1. Define the capability and representative tasks; search existing Major skills, project capabilities and permissible upstream prior art.
2. Inspect maturity, maintenance, licence, provenance, dependencies, authority and private assumptions.
3. Compare behavior, not names. Classify each candidate `USE AS-IS`, `CONFIGURE`, `INTEGRATE`, `HARVEST PATTERN`, `BUILD MISSING DELTA`, or `REJECT` with evidence.
4. Never copy incompatible content. Prefer the existing canonical skill and update it when overlap is material; never create a near-duplicate.
5. For harvested patterns, independently express only generic mechanisms and retain source/decision provenance.
6. Classify evaluation work as deterministic or reasoning. Use deterministic tools for tests, lint, formatting, git inspection, hashing, token counts, manifests, resource inspection and metrics; use model judgment only where interpretation is required.
7. Follow `skillify`: unchanged baseline, at least three comparable representative runs and median, held-out check for mutations, cost/latency comparison, 5% inconclusive band, material-improvement threshold, version, rollback and field monitoring.
8. Activation is proposal-only unless explicit mutation authority exists. One successful observation never becomes policy.

Stop on unknown licence, missing provenance, private-data leakage, duplicate capability, failed held-out evidence or absent activation authority.
