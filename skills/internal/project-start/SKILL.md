# Project Start

1. Clarify the desired user/business outcome.
2. Inspect existing code, history, assets, CI, docs and related repositories.
3. Confirm the canonical project/repository before creating anything. If a same/similar project may already exist locally or on GitHub, load `project-context-integrity` and `workspace-lifecycle-management` first; do not create a duplicate clone/folder because an expected path is missing.
4. Identify the biggest uncertainty and fastest credible proof.
5. Run competitive/product-pattern and open-source leverage audits where relevant.
6. Reduce broad requirements to P0 MVP / P1 next / P2 later.
7. Select the smallest useful end-to-end slice.
8. Define simple replaceable boundaries.
9. Install/register Major skills without loading irrelevant skill text.
10. For a genuinely new local repo, prefer the current canonical active-code workspace rather than an iCloud-synced Documents folder when practical; do not move an existing healthy repo solely to satisfy a folder convention.
11. Begin the first proof/vertical slice immediately; do not start infrastructure-first or speculative documentation.
