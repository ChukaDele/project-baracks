# Verified Presentation Storylining Synthesis

Status: verified reusable synthesis
Scope: cross-project, non-client-specific
Primary skill: `presentation-storylining`

## Core rule

Presentations should be built as arguments before they are built as slides.

Default sequence:

`decision -> structure -> evidence -> synthesis -> governing thought -> ghost deck -> slide proof -> critic -> render`

The transferable value from high-end consulting decks is not branding or visual imitation. It is disciplined problem framing, hypothesis testing, evidence hierarchy, synthesis, answer-first communication and rigorous slide-level logic.

## Durable principles

1. Start from the audience decision/action, not a slide template.
2. Define a governing question and, where appropriate, a provisional Day-1 answer.
3. Decompose the problem into a small set of decision-critical issues; use MECE only as a diagnostic.
4. Treat frameworks as tools, not outputs. Avoid framework salad.
5. Attack uncertain, high-impact assumptions first; explicitly define what evidence would disprove the current hypothesis.
6. Separate FACT, INFERENCE, ASSUMPTION and ESTIMATE for material claims.
7. Synthesize rather than summarize: retain only insights that change belief, action or decision.
8. Write one governing thought that the whole deck exists to establish.
9. Build a ghost deck of titles before full slide content.
10. Titles should be assertions/conclusions, not topic labels.
11. Horizontal logic: titles alone must tell a coherent, complete story.
12. Vertical logic: each slide's evidence must actually prove its title.
13. Build Slide Blueprints before visual layout: action title, purpose, proof, implication, caveat and likely exhibit archetype.
14. For executive audiences, lead with the answer and make trade-offs, risks, economics and the requested decision explicit.
15. Use an independent critic for consequential decks; ask what a skeptical CEO/CFO/partner/investor would challenge first.
16. Move secondary methodology and exhaustive backup to appendix; never hide material contradictions or risks there.
17. Render only after logic passes. Visual design serves the argument.
18. Stop when the argument is decision-useful; extra completeness is not automatically value.

## Presentation jobs

Classify the dominant job before structuring:

- DECIDE — board, strategy, investment, transformation, pricing.
- PERSUADE — sales, proposal, fundraising, partnership.
- ALIGN — executive update, steering, operating review.
- TEACH — onboarding, training, explainer.
- SHOW — case study, portfolio, conference/demo.

DECIDE and PERSUADE default to consulting-grade storylining. TEACH and SHOW may require less hypothesis-driven compression.

## Failure patterns to reject

- starting in PowerPoint/Figma before the story is understood;
- copying McKinsey/BCG/Bain aesthetics instead of reasoning discipline;
- topic titles such as `Market Overview` when a conclusion is available;
- dumping research into slides instead of synthesizing it;
- claims stronger than the evidence;
- assumptions presented as facts;
- using prestigious frameworks with no decision value;
- decks where the audience must perform the final synthesis;
- beautiful slides that cannot survive a skeptical read of the logic.

## Composition with Major

- `knowledge-work` owns research, evidence collection and decision reasoning.
- `presentation-storylining` owns transformation into governing thought, storyline, ghost deck, slide proof and presentation critic.
- `design-direction-and-taste` owns visual direction after the argument is sound.

## Learning loop

Capture future improvements from:

- user edits to governing thoughts or storyline;
- recurring slide deletions/reorders;
- objections from actual audiences;
- evidence gaps that reduce trust;
- deck structures that repeatedly improve decisions or conversion;
- cases where the consulting default is too rigid and a different narrative spine performs better.

Only promote new defaults after recurrence and validation under `learning-capture` / `skillify` policy.
